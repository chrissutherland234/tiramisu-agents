# Security policy

Do not report vulnerabilities in a public issue. Use the repository host's private security-advisory mechanism. Until a dedicated security contact is published, repository maintainers should coordinate disclosure through that private channel.

Never include live credentials, customer data, production workflow histories, private prompts, or exploit details in public logs, fixtures, screenshots, or issues.

The project is pre-release. Supported-version and disclosure timelines will be documented before the first public release.
